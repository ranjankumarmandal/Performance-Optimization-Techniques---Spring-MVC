1. JVM & MEMORY OPTIMIZATION
================================================================================

1.1 HEAP SIZING
- Set initial and max heap size to same value to avoid resize overhead
- -Xms4g -Xmx4g (adjust based on application needs)
- Use -XX:+UseG1GC for most applications (better than CMS/Parallel)
- For large heaps (>8GB), consider ZGC or Shenandoah
- -XX:MaxGCPauseMillis=200 (target GC pause time)

1.2 GC TUNING
- G1GC: -XX:G1HeapRegionSize=16m (adjust based on heap size)
- Enable GC logging: --add-opens=java.base/jdk.internal.misc=ALL-UNNAMED
- Use -XX:+UnlockExperimentalVMOptions -XX:+UseTransparentHugePages
- Disable explicit GC: -XX:+DisableExplicitGC
- For low-latency: -XX:+AlwaysPreTouch

1.3 METASPACE CONFIGURATION
- -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m
- Monitor metaspace usage to prevent ClassLoader leaks
- Use -XX:CompressedClassSpaceSize=256m

1.4 STRING DEDUPLICATION
- Enable: -XX:+UseStringDeduplication (with G1GC)
- Reduces memory footprint for duplicate strings
- -XX:StringDeduplicationAgeThreshold=3

1.5 NATIVE MEMORY TRACKING
- Enable for debugging: -XX:NativeMemoryTracking=detail
- Use jcmd VM.native_memory summary

1.6 JIT COMPILATION
- Tiered compilation: -XX:+TieredCompilation
- C2 compilation threshold: -XX:CompileThreshold=10000
- Use -XX:+PrintCompilation for debugging

2. SPRING BOOT CONFIGURATION OPTIMIZATION
================================================================================

2.1 LAZY INITIALIZATION
- Enable: spring.main.lazy-initialization=true
- Reduces startup time by initializing beans on demand
- Trade-off: first request latency may increase

2.2 AUTO-CONFIGURATION EXCLUSION
- Exclude unnecessary auto-configurations:
  @SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
- Use @ConditionalOnProperty to disable features
- Review actuator endpoints and disable unused ones

2.3 COMPONENT SCAN OPTIMIZATION
- Limit component scan scope: @ComponentScan(basePackages = {"com.example"})
- Use @ComponentScan.Filter to exclude unnecessary packages
- Avoid scanning large package trees

2.4 BEAN SCOPING
- Use prototype scope for stateful beans
- Use request scope for web-specific beans
- Avoid singleton for beans with mutable state
- Consider @RefreshScope for configuration updates

2.5 PROFILE-SPECIFIC CONFIGURATION
- Use application-prod.yml for production-specific settings
- Enable production profile: spring.profiles.active=prod
- Separate dev/test configurations

2.6 STARTUP OPTIMIZATION
- spring.main.lazy-initialization=true
- spring.main.allow-bean-definition-overriding=false
- spring.main.register-shutdown-hook=false (if not needed)
- Use spring-boot-starter-webflux instead of spring-boot-starter-web for reactive

2.7 PROPERTY LOADING
- Use spring.config.import to load specific config files
- Disable unnecessary config locations: spring.config.location
- Use spring.config.additional-location for overrides

3. SPRING MVC PERFORMANCE OPTIMIZATION
================================================================================

3.1 CONTROLLER OPTIMIZATION
- Avoid @ModelAttribute for large objects
- Use @ResponseBody with proper HTTP status codes
- Implement proper exception handling with @ControllerAdvice
- Use DTOs instead of entities in controllers

3.2 VIEW RESOLVER OPTIMIZATION
- Configure InternalResourceViewResolver with cache:
  <property name="cache" value="true"/>
- Use template caching in Thymeleaf: spring.thymeleaf.cache=true
- Pre-compile templates in production

3.3 STATIC RESOURCE HANDLING
- Enable cache headers: spring.web.resources.cache.period=3600
- Use CDN for static assets
- Enable GZIP compression: server.compression.enabled=true
- Configure resource chain caching: spring.web.resources.chain.cache=true

3.4 REQUEST MAPPING
- Use specific HTTP methods: @GetMapping, @PostMapping
- Use path variables instead of query parameters when possible
- Implement proper content negotiation with produces/consumes

3.5 INTERCEPTOR OPTIMIZATION
- Minimize interceptor logic
- Use ordered interceptors to short-circuit early
- Avoid expensive operations in preHandle

3.6 ASYNCHRONOUS CONTROLLERS
- Use @Async for long-running operations
- Configure AsyncTaskExecutor with proper pool size
- Use Callable<>, DeferredResult<>, or CompletableFuture<>
- Configure timeout: spring.mvc.async.request-timeout=30000

3.7 VALIDATION OPTIMIZATION
- Use manual validation for simple cases
- Cache validator instances
- Use @Validated at class level for method validation
- Disable Bean Validation if not needed: spring.validation.enabled=false

3.8 EXCEPTION HANDLING
- Use @ExceptionHandler for specific exceptions
- Implement global exception handler with @ControllerAdvice
- Return appropriate HTTP status codes
- Avoid stack traces in production responses

4. DATABASE & DATA ACCESS OPTIMIZATION
================================================================================

4.1 CONNECTION POOLING
- Use HikariCP (default in Spring Boot 2.x+):
  spring.datasource.hikari.maximum-pool-size=20
  spring.datasource.hikari.minimum-idle=10
  spring.datasource.hikari.idle-timeout=30000
  spring.datasource.hikari.connection-timeout=20000
  spring.datasource.hikari.max-lifetime=1800000
- Configure pool size based on database capacity
- Monitor pool metrics

4.2 JPA OPTIMIZATION
- Enable batch inserts: spring.jpa.properties.hibernate.jdbc.batch_size=50
- Use second-level cache: spring.jpa.properties.hibernate.cache.use_second_level_cache=true
- Configure query cache: spring.jpa.properties.hibernate.cache.use_query_cache=true
- Use @Cacheable on frequently accessed entities
- Enable statistics in development: spring.jpa.properties.hibernate.generate_statistics=true

4.3 LAZY LOADING
- Use @ManyToOne(fetch = FetchType.LAZY)
- Use @OneToMany(fetch = FetchType.LAZY)
- Avoid N+1 query problem with JOIN FETCH
- Use EntityGraph for complex queries

4.4 QUERY OPTIMIZATION
- Use @Query with native SQL for complex queries
- Create proper database indexes
- Use pagination: Pageable, PageRequest
- Avoid SELECT * - specify needed columns
- Use projection interfaces for partial data

4.5 TRANSACTION MANAGEMENT
- Use @Transactional(readOnly = true) for read operations
- Set appropriate isolation levels
- Keep transactions short
- Avoid nested transactions
- Use @Transactional(propagation = Propagation.REQUIRES_NEW) when needed

4.6 DATABASE-SPECIFIC OPTIMIZATION
- MySQL: use InnoDB, configure innodb_buffer_pool_size
- PostgreSQL: configure shared_buffers, work_mem
- Use connection pooling at database level
- Enable query logging in development only

4.7 JDBC TEMPLATE
- Use JdbcTemplate for simple queries (faster than JPA)
- Batch operations with JdbcTemplate.batchUpdate
- Use SimpleJdbcInsert for inserts

4.8 FLYWAY/LIQUIBASE OPTIMIZATION
- Disable in production if schema is stable: spring.flyway.enabled=false
- Use baseline version for existing databases
- Group migrations to reduce round trips

5. CACHING STRATEGIES
================================================================================

5.1 SPRING CACHE ABSTRACTION
- Enable caching: @EnableCaching
- Use @Cacheable for read-heavy operations
- Use @CachePut for updates
- Use @CacheEvict for invalidation
- Configure cache manager: @Bean CacheManager

5.2 CACHE IMPLEMENTATIONS
- Caffeine (recommended for local cache):
  spring.cache.type=caffeine
  spring.cache.caffeine.spec=maximumSize=1000,expireAfterWrite=10m
- Redis for distributed cache:
  spring.cache.type=redis
  spring.redis.timeout=60000
- Hazelcast for clustering
- Ehcache for simple use cases

5.3 CACHE KEY STRATEGIES
- Custom key generators: @Cacheable(keyGenerator = "customKeyGenerator")
- Use SpEL expressions: @Cacheable(key = "#user.id")
- Consider key collision scenarios

5.4 CACHE EVICTION
- Time-based eviction: expireAfterWrite, expireAfterAccess
- Size-based eviction: maximumSize
- Manual eviction: @CacheEvict(allEntries = true)
- Use @Caching for multiple cache operations

5.5 CACHE TIERING
- Multi-level caching (L1: local, L2: distributed)
- Cache-aside pattern
- Read-through/write-through patterns
- Consider cache warming strategies

5.6 CACHE MONITORING
- Monitor hit ratio
- Track eviction rates
- Monitor cache size
- Use Micrometer metrics

6. ASYNCHRONOUS PROCESSING
================================================================================

6.1 SPRING ASYNC
- Enable: @EnableAsync
- Configure executor: @Bean Executor asyncExecutor
- Use @Async on methods
- Configure thread pool: ThreadPoolTaskExecutor
  - corePoolSize: number of CPU cores
  - maxPoolSize: 2x corePoolSize
  - queueCapacity: 1000
  - keepAliveSeconds: 60

6.2 SPRING WEBFLUX
- Use reactive stack for I/O-bound applications
- Use Netty instead of Tomcat: spring.main.web-application-type=reactive
- Use Mono<> for single values, Flux<> for streams
- Backpressure handling
- Non-blocking I/O operations

6.3 MESSAGE QUEUES
- Use RabbitMQ for reliable messaging
- Use Kafka for high-throughput streaming
- Configure prefetch count
- Use dead letter queues
- Implement proper error handling

6.4 SCHEDULING
- Use @Scheduled with fixedRate/fixedDelay
- Configure TaskScheduler for complex scheduling
- Use cron expressions for precise timing
- Consider distributed scheduling with Quartz

6.5 EVENT-DRIVEN ARCHITECTURE
- Use ApplicationEvent for internal events
- Use @EventListener for event handling
- Configure @Async for event listeners
- Use @TransactionalEventListener for transaction-bound events

7. CONNECTION POOLING
================================================================================

7.1 HTTP CLIENT POOLING
- Configure Apache HttpClient with connection pool:
  - MaxTotal: 200
  - DefaultMaxPerRoute: 100
- Use connection time-to-live
- Enable keep-alive
- Configure connection timeout, socket timeout

7.2 DATABASE CONNECTION POOLING
- HikariCP configuration:
  - maximumPoolSize: (core_count * 2) + effective_spindle_count
  - minimumIdle: same as maximumPoolSize for stable systems
  - connectionTimeout: 30000ms
  - idleTimeout: 600000ms
  - maxLifetime: 1800000ms
- Monitor pool metrics
- Use validation query: SELECT 1

7.3 REDIS CONNECTION POOLING
- Configure lettuce pool:
  spring.redis.lettuce.pool.max-active=8
  spring.redis.lettuce.pool.max-idle=8
  spring.redis.lettuce.pool.min-idle=0
- Use connection timeout
- Enable command timeout

7.4 RABBITMQ CONNECTION POOLING
- Configure connection factory with cache mode
- Use channel pooling
- Configure publisher confirms
- Set appropriate prefetch count

8. HTTP & REST OPTIMIZATION
================================================================================

8.1 COMPRESSION
- Enable GZIP: server.compression.enabled=true
- Configure mime types: server.compression.mime-types=application/json,application/xml,text/html,text/xml,text/plain
- Set minimum response size: server.compression.min-response-size=1024

8.2 HTTP/2
- Enable HTTP/2: server.http2.enabled=true
- Requires SSL/TLS in most cases
- Use ALPN for protocol negotiation

8.3 KEEP-ALIVE
- Configure keep-alive timeout: server.tomcat.keep-alive-timeout=30000
- Set max keep-alive requests: server.tomcat.max-keep-alive-requests=100
- Enable connection pooling

8.4 HTTP CLIENT OPTIMIZATION
- Use RestTemplate with connection pooling
- Use WebClient for reactive (Spring 5+)
- Configure timeouts:
  - connection timeout
  - read timeout
  - write timeout
- Use connection keep-alive

8.5 API DESIGN
- Use proper HTTP verbs (GET, POST, PUT, DELETE, PATCH)
- Implement pagination for large datasets
- Use field selection/projection
- Implement rate limiting
- Use API versioning

8.6 JSON OPTIMIZATION
- Use Jackson with proper configuration:
  spring.jackson.serialization.write-dates-as-timestamps=false
  spring.jackson.default-property-inclusion=non_null
- Use @JsonView for partial serialization
- Consider Protocol Buffers for high-performance scenarios
- Use @JsonIgnore for sensitive data

8.7 CONTENT NEGOTIATION
- Configure content negotiation manager
- Use produces/consumes in @RequestMapping
- Implement custom message converters if needed
