1. JVM & MEMORY OPTIMIZATION
================================================================================

1.1 HEAP SIZING
- Set initial and max heap size to same value to avoid resize overhead
- -Xms4g -Xmx4g (adjust based on application needs)
- Use -XX:+UseG1GC for most applications (better than CMS/Parallel)
- For large heaps (>8GB), consider ZGC or Shenandoah
- -XX:MaxGCPauseMillis=200 (target GC pause time)

1.2 GC TUNING
- G1GC: -XX:G1HeapRegionSize=16m (adjust based on heap size)
- Enable GC logging: --add-opens=java.base/jdk.internal.misc=ALL-UNNAMED
- Use -XX:+UnlockExperimentalVMOptions -XX:+UseTransparentHugePages
- Disable explicit GC: -XX:+DisableExplicitGC
- For low-latency: -XX:+AlwaysPreTouch

1.3 METASPACE CONFIGURATION
- -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m
- Monitor metaspace usage to prevent ClassLoader leaks
- Use -XX:CompressedClassSpaceSize=256m

1.4 STRING DEDUPLICATION
- Enable: -XX:+UseStringDeduplication (with G1GC)
- Reduces memory footprint for duplicate strings
- -XX:StringDeduplicationAgeThreshold=3

1.5 NATIVE MEMORY TRACKING
- Enable for debugging: -XX:NativeMemoryTracking=detail
- Use jcmd VM.native_memory summary

1.6 JIT COMPILATION
- Tiered compilation: -XX:+TieredCompilation
- C2 compilation threshold: -XX:CompileThreshold=10000
- Use -XX:+PrintCompilation for debugging

2. SPRING BOOT CONFIGURATION OPTIMIZATION
================================================================================

2.1 LAZY INITIALIZATION
- Enable: spring.main.lazy-initialization=true
- Reduces startup time by initializing beans on demand
- Trade-off: first request latency may increase

2.2 AUTO-CONFIGURATION EXCLUSION
- Exclude unnecessary auto-configurations:
  @SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
- Use @ConditionalOnProperty to disable features
- Review actuator endpoints and disable unused ones

2.3 COMPONENT SCAN OPTIMIZATION
- Limit component scan scope: @ComponentScan(basePackages = {"com.example"})
- Use @ComponentScan.Filter to exclude unnecessary packages
- Avoid scanning large package trees

2.4 BEAN SCOPING
- Use prototype scope for stateful beans
- Use request scope for web-specific beans
- Avoid singleton for beans with mutable state
- Consider @RefreshScope for configuration updates

2.5 PROFILE-SPECIFIC CONFIGURATION
- Use application-prod.yml for production-specific settings
- Enable production profile: spring.profiles.active=prod
- Separate dev/test configurations

2.6 STARTUP OPTIMIZATION
- spring.main.lazy-initialization=true
- spring.main.allow-bean-definition-overriding=false
- spring.main.register-shutdown-hook=false (if not needed)
- Use spring-boot-starter-webflux instead of spring-boot-starter-web for reactive

2.7 PROPERTY LOADING
- Use spring.config.import to load specific config files
- Disable unnecessary config locations: spring.config.location
- Use spring.config.additional-location for overrides

3. SPRING MVC PERFORMANCE OPTIMIZATION
================================================================================

3.1 CONTROLLER OPTIMIZATION
- Avoid @ModelAttribute for large objects
- Use @ResponseBody with proper HTTP status codes
- Implement proper exception handling with @ControllerAdvice
- Use DTOs instead of entities in controllers

3.2 VIEW RESOLVER OPTIMIZATION
- Configure InternalResourceViewResolver with cache:
  <property name="cache" value="true"/>
- Use template caching in Thymeleaf: spring.thymeleaf.cache=true
- Pre-compile templates in production

3.3 STATIC RESOURCE HANDLING
- Enable cache headers: spring.web.resources.cache.period=3600
- Use CDN for static assets
- Enable GZIP compression: server.compression.enabled=true
- Configure resource chain caching: spring.web.resources.chain.cache=true

3.4 REQUEST MAPPING
- Use specific HTTP methods: @GetMapping, @PostMapping
- Use path variables instead of query parameters when possible
- Implement proper content negotiation with produces/consumes

3.5 INTERCEPTOR OPTIMIZATION
- Minimize interceptor logic
- Use ordered interceptors to short-circuit early
- Avoid expensive operations in preHandle

3.6 ASYNCHRONOUS CONTROLLERS
- Use @Async for long-running operations
- Configure AsyncTaskExecutor with proper pool size
- Use Callable<>, DeferredResult<>, or CompletableFuture<>
- Configure timeout: spring.mvc.async.request-timeout=30000

3.7 VALIDATION OPTIMIZATION
- Use manual validation for simple cases
- Cache validator instances
- Use @Validated at class level for method validation
- Disable Bean Validation if not needed: spring.validation.enabled=false

3.8 EXCEPTION HANDLING
- Use @ExceptionHandler for specific exceptions
- Implement global exception handler with @ControllerAdvice
- Return appropriate HTTP status codes
- Avoid stack traces in production responses
